## 2026-09-22 — الجلسة 3: الدورة الكاملة (M2–M6)

- M2: اكتشاف محدود وتأهيل بالأدلة عبر LangGraph بحفظ دائم في مخطط `sales_graph`، وإثراء محدود، وفحص سياسة بإصلاح واحد.
- M3: اعتماد مرتبط بإصدار المسودة ومحتواها، وآلة حالة إرسال بثلاث مراحل بلا إعادة إرسال عمياء، وواتساب يدوي بتأكيد بشري.
- M4: مزامنة IMAP بمؤشر، وربط الردود بـMessage-ID، وطابور «تحتاج ربطًا»، وإيقاف فوري عند طلب العميل، وويب هوك Hostinger كمنبّه، وبوت تيليجرام برموز نداء مبهمة.
- M5: مجدول بنوافذ سماح بلا تعويض، وملخص يومي، وتنظيف واحتفاظ، وصفحة «اليوم» بالتنبيهات وأزرار الإيقاف.
- M6: E2E بمتصفح حقيقي، وتقييم نماذج على 30 حالة موسومة، ونسخ احتياطي مع استرجاع مُختبر، ودليل إطلاق كامل.
- واجهة: الموافقات، الفرص، تفاصيل الفرصة، المحادثات، التشغيل والسجلات، وإضافة جهات اتصال يدويًا، وواجهة JSON لـSPEC §12.
- أخطاء اكتشفتها الاختبارات: حالة فرصة تضيع لتعديل كائن من جلسة مغلقة، وتمرير أفقي على الهاتف في الإعدادات، وأدوات PostgreSQL على Windows (ترتيب الوسائط والمسار العربي).
- النتيجة: 180 اختبارًا ناجحًا، ruff وmypy نظيفان، ولا إرسال حقيقي (OUTBOUND_ENABLED=false).

## 2026-09-25 — الجلسة 5: مراجعة ما قبل النشر على Render

- GitHub مطابق للنسخة المحلية (3449201) قبل البدء.
- `render.yaml` كان سيفشل: Render لا يقبل `sync: false` داخل مجموعة متغيرات (مؤكد من مواصفة Blueprint).
  الأسرار صارت على خدمة الويب، والعامل ينسخها بـ`fromService`/`envVarKey`. أُزيلت خدمة cron (العامل يجدول كل دقيقة).
  الخطط بالاسم الجديد `0.5c-512mb` (Starter سابقًا).
- `tzdata` صارت اعتمادية صريحة: كانت تُثبت على Windows فقط (عبر psycopg)، وصورة Linux قد تخلو من قاعدة المناطق الزمنية.
- الحافظ الدائم يضبط `search_path` بأمر SET بعد الاتصال بدل معامل بدء قد يرفضه pooler.
- لا حساب مدفوع في Render: خدمة واحدة مجانية. `RUN_WORKER_IN_WEB` يشغّل العامل داخل الويب، و`MIGRATE_ON_START` يطبق الترحيلات من `scripts/start-web.sh` (القرار 0009).
- قياس الذاكرة محليًا مع العامل المدمج: نحو 120 ميجابايت (حد الخطة المجانية 512).
- ملاحظة: `.env` المحلي صار يشير إلى Supabase الحقيقية (Mumbai). اختبار محلي اتصل بها ثوانٍ وفشل لغياب الجداول؛ لم يُكتب شيء. أداة الاختبار (`pytest`) لا تتأثر لأنها تستخدم `sales_test` المحلية.
- أول نشر للمالك على Render (خدمة مجانية): «Internal Server Error». `/health/ready` = 503 لأن Supabase بلا جداول (الترحيلات لم تعمل على Render).
  طُبقت الترحيلات 0001–0003 وجداول الحافظ على Supabase (PostgreSQL 17.6) من جهاز التطوير بطلب المالك إصلاح النشر؛ القاعدة كانت فارغة. بعدها `/health/ready` = 200 و`env=production`.
  لا نبضة عامل على Render: `RUN_WORKER_IN_WEB`/`MIGRATE_ON_START` غير مضبوطين هناك أو النشر من commit أقدم.
- رسائل التطبيق كانت تختفي تحت uvicorn CLI (لا إعداد للسجل)؛ صار `create_app` يضبطه. نقاط الصحة تقبل HEAD لمراقبي التوفر.
