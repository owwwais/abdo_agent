# دليل التشغيل والإطلاق

هذا الدليل يأخذك من «يعمل على جهازي» إلى «يعمل على الإنترنت ويجد عملاء ويراسلهم بعد اعتمادي». اتبع المراحل بالترتيب.

> **قاعدتان ثابتتان**
> 1. لا تلصق أي مفتاح في محادثة أو رسالة أو مستند مشترك. المفاتيح مكانها ملف `.env` على جهازك، أو لوحة Render، أو صفحة الإعدادات داخل المنصة (تُحفظ مشفرة ولا تُعرض مرة أخرى).
> 2. لا يخرج أي بريد لأي عميل إلا بعد: اعتمادك لنص الرسالة بعينه، وتوثيق سند التواصل مع المستلم، و`OUTBOUND_ENABLED=true` الذي تضبطه أنت بيدك. واتساب يدوي دائمًا.

## 1) خريطة المفاتيح: ما هو، ومن أين، وأين يوضع

| المفتاح | من أين تحصل عليه | أين تضعه | إلزامي؟ |
|---|---|---|---|
| `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` | Supabase ← Connect، أو Settings ← API Keys | `.env` محليًا، ومجموعة المتغيرات في Render | للإنتاج نعم |
| `DATABASE_URL` | Supabase ← Connect ← **Session pooler** + كلمة مرور القاعدة | `.env` / Render | نعم |
| `SESSION_SECRET` و`DATA_HASH_KEY` و`SECRETS_ENCRYPTION_KEY` | تُولَّد: `uv run python scripts/gen_secrets.py` | `.env` / Render | نعم |
| `HOSTINGER_WEBHOOK_SECRET` | hPanel ← Emails ← Agentic mail ← Webhooks (يظهر مرة واحدة) | `.env` / Render (أو خانته في الإعدادات ← البريد) | لاستقبال فوري للردود |
| كلمة مرور صندوق البريد | hPanel ← Emails ← Mailboxes | **صفحة الإعدادات ← البريد** | للإرسال |
| مفتاح النموذج (Anthropic أو OpenAI أو Gemini أو مزود متوافق) | لوحة المزود (القسم 3.3) | **صفحة الإعدادات ← النماذج** | للتشغيل الفعلي |
| مفتاح البحث: Tavily (مجاني بلا بطاقة) أو Brave | app.tavily.com أو api-dashboard.search.brave.com | **صفحة الإعدادات ← البحث** | لمصدر «بحث ويب» |
| مفتاح Google Maps (Places API) | Google Cloud Console (القسم 3.4 ج) | **صفحة الإعدادات ← البحث** | لمصدر «خرائط Google» |
| رمز بوت تيليجرام ومعرف المجموعة | @BotFather | **صفحة الإعدادات ← تيليجرام** | اختياري (الموافقة من اللوحة تكفي) |
| `OUTBOUND_ENABLED` و`OUTBOUND_ALLOWLIST` | قرارك | `.env` / Render فقط (عمدًا ليس في الصفحة) | — |

**القاعدة:** مفاتيح البنية (القاعدة، Supabase، الأسرار الداخلية، مفتاح الإيقاف العام) في ملف البيئة. مفاتيح التكاملات (النماذج، البريد، البحث، تيليجرام) في صفحة الإعدادات، وتُشفَّر بـ`SECRETS_ENCRYPTION_KEY`. ما يُحفظ في الصفحة يتقدم على ما في `.env`.

## 2) المرحلة أ: التشغيل على جهازك الآن (بلا أي مفتاح خارجي)

في PowerShell أو Git Bash داخل مجلد المشروع:

```bash
uv sync
uv run python scripts/localdb.py start
uv run alembic upgrade head
uv run python scripts/seed_demo.py
uv run python -m app.main
```

وفي طرفية ثانية:

```bash
uv run python -m app.jobs.worker
```

افتح `http://127.0.0.1:8000/login` واضغط «مالك تجريبي». كل شيء اصطناعي حتى تضيف المفاتيح: البحث يعيد 3 جهات تجريبية، والنموذج يُحاكى، والبريد يذهب إلى صندوق وهمي.

**جرّب الدورة كاملة في 5 دقائق:**
1. المنتجات ← «[تجريبي] منظم المواعيد» ← تفعيل.
2. المصادر ← «بحث ويب» ← فحص عينة ← أكّد البنود الثلاثة ← تأكيد وتفعيل.
3. التشغيل ← «دورة اكتشاف اليوم»، ثم «معالجة فرصة واحدة».
4. الفرص ← «مجمع عيادات الواحة» ← الشركة ← «إضافة جهة اتصال يدويًا» (بريد وهمي) ← عد للفرصة ← «معالجة الآن».
5. الموافقات ← وثّق الأهلية بسند ← «اعتماد وإرسال» ← ستجد الرسالة في محادثة الفرصة (إرسال اصطناعي).

## 3) المرحلة ب: الحصول على المفاتيح خطوة بخطوة

### 3.1 Supabase (الدخول وقاعدة البيانات)

1. أنشئ مشروعًا في [supabase.com](https://supabase.com). اختر كلمة مرور قوية للقاعدة واحفظها في مدير كلمات المرور. اختر المنطقة الأقرب لخادمك؛ ملف `render.yaml` يستخدم Frankfurt، فالأنسب «Central EU (Frankfurt)». اختيار المنطقة قرار بيانات يعود لكم.
2. **الرابط والمفتاح المنشور:** زر **Connect** أعلى صفحة المشروع، أو **Settings ← API Keys**. خذ رابط المشروع `https://<ref>.supabase.co` والمفتاح الذي يبدأ بـ`sb_publishable_`. هذا المفتاح آمن للكشف بطبيعته. **لا تستخدم** `sb_secret_` ولا `service_role` في هذا التطبيق.
3. **رابط القاعدة:** من **Connect** اختر **Session pooler** (المنفذ 5432). يعمل مع الخوادم التي لا تدعم IPv6 مثل Render، ويدعم الاتصالات الطويلة التي يحتاجها العامل. الصيغة:
   `postgresql://postgres.<project-ref>:<كلمة-مرور-القاعدة>@<pooler-host>:5432/postgres`
   لا تستخدم Transaction pooler (المنفذ 6543).
4. **مفاتيح توقيع JWT:** افتح **Settings ← JWT Keys** وتأكد أن المفتاح الحالي غير متماثل (ECC P-256 أو RSA)، لا «Legacy HS256». إن كان قديمًا، رحّله ثم دوّر المفاتيح من الصفحة نفسها.
   **فحص سريع:** افتح في المتصفح `https://<ref>.supabase.co/auth/v1/.well-known/jwks.json`. يجب أن تظهر قائمة `keys` غير فارغة.
5. **أغلق التسجيل العام:** **Authentication ← Sign In / Providers**، وأطفئ **Allow new users to sign up**.
6. **أنشئ حسابك:** **Authentication ← Users ← Add user ← Create new user**. أدخل البريد وكلمة المرور وفعّل **Auto Confirm User**، ثم انسخ **User UID**. كرر لكل مؤسس.

### 3.2 الأسرار الداخلية

```bash
uv run python scripts/gen_secrets.py --print
```

يطبع ثلاث قيم جديدة لـ`SESSION_SECRET` و`DATA_HASH_KEY` و`SECRETS_ENCRYPTION_KEY`. استعمل قيمًا مختلفة للإنتاج عن جهازك.
**احفظ `DATA_HASH_KEY` و`SECRETS_ENCRYPTION_KEY` في مدير كلمات المرور:**
- تغيير الأول يكسر مطابقة سجل منع التواصل.
- فقدان الثاني يعني إعادة إدخال كل مفاتيح صفحة الإعدادات.

### 3.3 نموذج الذكاء الاصطناعي (اختر ما تحب)

المنصة تقبل أي مزود مما يلي، ويمكنك اختيار نموذج مختلف لكل دور:
- دور **الاستخراج**: تخطيط البحث وتصنيف الردود. نموذج سريع رخيص يكفيه.
- دور **التأهيل والصياغة**: تقييم الفرص وكتابة الرسائل. يستحق نموذجًا أقوى.

| المزود | أين المفتاح | ملاحظة |
|---|---|---|
| Anthropic (Claude) | [platform.claude.com/settings/keys](https://platform.claude.com/settings/keys) ← Create Key | يبدأ بـ`sk-ant-` ويُعرض مرة واحدة. أسعار نماذج Claude تُعبأ تلقائيًا في الصفحة |
| OpenAI | [platform.openai.com/api-keys](https://platform.openai.com/api-keys) | أدخل السعر يدويًا من صفحة أسعارهم |
| Google Gemini | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) | أدخل السعر يدويًا |
| متوافق مع OpenAI (مثل OpenRouter) | لوحة ذلك المزود + رابطه الأساسي | أدخل الرابط والسعر يدويًا |

ضع حدًا للإنفاق من لوحة المزود نفسه أيضًا. هذا حماية إضافية فوق ميزانية المنصة.

### 3.4 البحث: اختر واحدًا أو أكثر

دورة الاكتشاف تستهلك 1–3 طلبات يوميًا (نحو 90 شهريًا)، وكل الخيارات أدناه مجانية فعليًا عند هذا الحجم. واجهة Google للبحث العام مغلقة أمام العملاء الجدد، وواجهة Bing توقفت؛ ولهذا نستخدم هذه (القرار 0008).

**أ) Tavily — الأسهل للبدء (مجاني بلا بطاقة)**
1. سجّل في [app.tavily.com](https://app.tavily.com) وانسخ المفتاح (`tvly-…`).
2. الخطة المجانية 1000 طلب شهريًا. في الإعدادات اكتب السعر **0**.

**ب) Brave Search — فهرس مستقل**
1. سجّل في [api-dashboard.search.brave.com](https://api-dashboard.search.brave.com/register) واشترك في خطة **Search**.
2. السعر المعلن 5$ لكل 1000 طلب، مع رصيد 5$ شهريًا (≈1000 طلب). البطاقة للتحقق فقط.
3. من **API Keys** انسخ المفتاح. في الإعدادات اكتب السعر **5**.

**ج) خرائط Google — منشآت بالنشاط والمدينة**
1. [console.cloud.google.com](https://console.cloud.google.com): أنشئ مشروعًا، واربط حساب فوترة (Billing). الربط إلزامي حتى للاستخدام المجاني.
2. **APIs & Services ← Library ← Places API (New) ← Enable**.
3. **APIs & Services ← Credentials ← Create credentials ← API key**. ثم **Edit API key**: في «API restrictions» اختر **Places API (New)** فقط.
4. أول 1000 طلب شهريًا مجانية (كل طلب يعيد حتى 20 منشأة)، ثم بسعر فئة Text Search Enterprise. في الإعدادات اكتب السعر **0** ما دمت ضمن الحصة، وضع حدًا يوميًا من **Quotas** في Google Cloud كحماية إضافية.
5. **ما يُخزن:** معرف المكان فقط، كما تشترط Google. الاسم والوصف والتواصل تُقرأ من موقع المنشأة نفسها. المنشأة بلا موقع إلكتروني تُعد في سجل التشغيل ولا تُخزن؛ أضفها يدويًا إن أردت.

لإضافة منصات أخرى: [adding-sources.md](adding-sources.md).

### 3.5 Hostinger: البريد والويب هوك

**أ) صندوق البريد**
- hPanel ← **Emails** ← نطاقك ← **Mailboxes**. أنشئ صندوقًا للمبيعات، مثل `sales@yourdomain.com`، واحفظ كلمة مروره.
- الخوادم (تضبطها المنصة تلقائيًا عند اختيار Hostinger):
  - الإرسال: `smtp.hostinger.com`، المنفذ 465، SSL.
  - الاستقبال: `imap.hostinger.com`، المنفذ 993، SSL.
- اسم المستخدم هو عنوان البريد كاملًا.
- تأكد أن سجلات SPF وDKIM وDMARC للنطاق مضبوطة في hPanel؛ بدونها تذهب رسائلك إلى البريد المزعج.

**ب) الويب هوك (بعد أن يصبح للمنصة رابط https عام، أي بعد المرحلة د)**
1. hPanel ← **Emails** ← نطاقك ← **Agentic mail** ← **Webhooks** ← **Add webhook**.
2. اختر صندوق المبيعات، والصق الرابط: `https://<رابط-المنصة>/webhooks/email/hostinger` (تجده أيضًا في الإعدادات ← البريد).
3. الحدث: `message.received`.
4. **انسخ السر فورًا**؛ Hostinger يعرضه مرة واحدة. ضعه في `HOSTINGER_WEBHOOK_SECRET` في Render، أو في خانة «سر ويب هوك Hostinger» في الإعدادات ← البريد.
5. اضغط **Test** وراجع **Recent deliveries**: يجب أن يكون الرد 200.
   الرسالة التجريبية تُسجَّل ولا تُحلَّل؛ الويب هوك مجرد منبّه، والمنصة تقرأ الرسائل الفعلية عبر IMAP.

على جهازك المحلي لا يمكن لـHostinger الوصول إلى `localhost`، والمزامنة الدورية عبر IMAP (كل 10 دقائق افتراضيًا، ويمكن تقليلها حتى دقيقتين من الإعدادات ← البريد) تغطي ذلك.

### 3.6 تيليجرام (اختياري لكنه مريح)

1. في تيليجرام افتح **@BotFather**، ثم `/newbot`، واختر الاسم، وانسخ **الرمز**.
2. أنشئ مجموعة للمؤسسين وأضف البوت إليها.
3. **معرف المجموعة:** أرسل في المجموعة `/start@اسم_البوت`، ثم افتح في متصفحك `https://api.telegram.org/bot<الرمز>/getUpdates` وابحث عن `"chat":{"id":-100...`. هذا هو المعرف.
   افعل هذا **قبل** تفعيل تيليجرام في المنصة، لأن العامل يستهلك التحديثات بعد التفعيل.

## 4) المرحلة ج: الإدخال في المنصة (صفحة الإعدادات)

ادخل كمالك ← **الإعدادات**. بعد الحفظ، الخانات السرية تُفرَّغ وتظهر حالتها فقط («محفوظ في الإعدادات» أو «من ملف البيئة»).

| التبويب | ماذا تُدخل | زر التحقق |
|---|---|---|
| **النماذج** | مفتاح مزودك، ثم لكل دور: المزود والنموذج (زر «جلب النماذج المتاحة» يعرض القائمة الحقيقية)، والسعر لكل مليون توكن، وعلّم مربع «راجعنا سياسة معالجة البيانات…» | «اختبار» لكل دور: استدعاء صغير (≤600 توكن) يُسجَّل في الاستهلاك |
| **البريد** | المزود SMTP، الإعداد المسبق Hostinger، البريد وكلمة مروره، اسم المرسل، التوقيع، سطر إيقاف التواصل، رابط الحجز (اختياري)، حد الإرسال اليومي | «اختبار الاتصال» يفحص SMTP وIMAP ويكتشف مجلد المرسل، و«إرسال رسالة اختبار» إلى بريدك أنت فقط |
| **البحث** | مزود البحث (Tavily أو Brave) ومفتاحه وسعره (0 أو 5)، والدولة `SA`، واللغة `ar`؛ وقسم خرائط Google: المفتاح والسعر (0 ضمن الحصة) | «اختبار البحث» و«اختبار خرائط Google»: طلب واحد لكل منهما |
| **تيليجرام** | فعّل، والرمز، ومعرف المجموعة | «اختبار البوت»، و«إرسال رسالة اختبار للمجموعة» |
| **التشغيل** | الميزانية اليومية والشهرية، والمواعيد، وعدد الفرص يوميًا، وحد التأهيل (70) | لوحة «جاهزية التشغيل الفعلي» تسرد ما ينقص |
| **الأعضاء والنظام** | «إنشاء رمز ربط»، ثم أرسل للبوت في محادثة خاصة: `/link الرمز` | يظهر اسمك مربوطًا |

**تأكد أن النموذج يفهم منتجك:** المنتجات ← منتجك ← «اختبر فهم النموذج للمنتج». يعيد النموذج صياغة المشكلة والعميل والخصائص وما لن يدّعيه. إن فهم خطأً، فصحّح الوصف قبل أي دورة.

**قيّم النموذج قبل اعتماده** على 30 ردًا اصطناعيًا تشمل طلبات إيقاف ومحاولات حقن. التكلفة سنتات ويطبع حدها الأقصى قبل البدء:

```bash
uv run python scripts/eval_models.py --yes
```

الحكم «مقبول» يتطلب ثلاثة شروط: دقة 80% فأكثر، والتقاط كل طلبات الإيقاف، وعدم نجاح أي حقن.

## 5) المرحلة د: الإطلاق على الإنترنت (Render + Supabase)

طريقتان:
- **5.أ مجانية:** خدمة ويب واحدة يدور فيها العامل.
- **5.ب مدفوعة:** Blueprint بخدمتين، ويب وعامل منفصلين. تنتقل إليها لاحقًا دون تغيير في الكود.

### 5.أ الخطة المجانية: خدمة واحدة

خطة Render المجانية تشمل خدمات الويب فقط، لا Background Worker، والخدمة المجانية تنام بعد 15 دقيقة بلا زيارات. لذلك:
- يعمل العامل **داخل** خدمة الويب (`RUN_WORKER_IN_WEB=true`).
- تُنشأ الجداول عند كل إقلاع (`MIGRATE_ON_START=true`).
- مراقب خارجي مجاني يطرق الخدمة كل 10 دقائق فلا تنام.

1. [dashboard.render.com](https://dashboard.render.com) ← **New ← Web Service** (لا Blueprint) ← اربط GitHub ← اختر `abdo_agent`.
2. الإعدادات:
   - **Language:** Docker.
   - **Branch:** `main`.
   - **Region:** الأقرب إلى منطقة Supabase. لقاعدة في Mumbai (`ap-south-1`) اختر **Singapore**؛ لقاعدة في Frankfurt اختر Frankfurt. كل صفحة تستعلم القاعدة مرات عدة، فالقرب يهم.
   - **Instance Type:** **Free**.
3. **Environment Variables:** اضغط **Add from .env** والصق التالي بقيمك (يمكن جمعها كلها مرة واحدة):
   ```
   APP_ENV=production
   APP_TIMEZONE=Asia/Riyadh
   APP_BASE_URL=https://<اسم-الخدمة>.onrender.com
   DATABASE_URL=<رابط Session pooler>
   SUPABASE_URL=<...>
   SUPABASE_PUBLISHABLE_KEY=<...>
   SESSION_SECRET=<...>
   DATA_HASH_KEY=<...>
   SECRETS_ENCRYPTION_KEY=<...>
   RUN_WORKER_IN_WEB=true
   MIGRATE_ON_START=true
   ```
   الأسرار الثلاثة قيم جديدة من `gen_secrets.py --print` (3.2)، لا قيم جهازك.
4. **Advanced:**
   - **Health Check Path** = `/health/ready`.
   - **Auto-Deploy** = Off إن أردت أن تنشر بيدك فقط.
5. **Create Web Service.** البناء الأول يستغرق بضع دقائق. في السجل (Logs) سترى «تطبيق الترحيلات قبل الإقلاع…» ثم `worker … started`.
6. إن اختلف رابط الخدمة عما كتبته في `APP_BASE_URL`، صححه من **Environment** ثم **Manual Deploy**.
7. **ابقِها مستيقظة:**
   - في [uptimerobot.com](https://uptimerobot.com) أو [cron-job.org](https://cron-job.org) (مجانيان) أنشئ مراقبًا يطلب `https://<رابطك>/health/live` كل 10 دقائق.
   - بدونه تنام الخدمة، فتفوت دورة الاكتشاف ونوافذ المعالجة وتتأخر المزامنة. النظام لا يعوّض الفائت، وهذا مقصود.
8. تابع من الخطوة 5 في 5.ب أدناه (التحقق، `add_member.py`، الدخول، ويب هوك Hostinger).

**حدود الخطة المجانية (اعرفها قبل الاعتماد عليها):**
- **750 ساعة مجانية شهريًا لكل حساب:** تكفي خدمة واحدة تعمل 24/7. لا تُنشئ خدمة مجانية ثانية وإلا نفدت الساعات.
- **معالج بطيء:** الصفحات أبطأ من الخطة المدفوعة، والذاكرة كافية (التطبيق مع العامل يستهلك نحو 120 ميجابايت محليًا).
- **إعادة التشغيل:** قد تعيد Render تشغيل الخدمة المجانية في أي وقت. العامل يستأنف المهام المعلقة تلقائيًا، والإرسال المنقطع يصبح «تسليم غير معروف» ولا يُعاد.
- **سياسة الإبقاء مستيقظًا:** وثائق Render لا تذكر منع طرق الخدمة لإبقائها مستيقظة، لكنها قد تغيّر سياستها.
- **للترقية لاحقًا:** غيّر Instance Type إلى خطة مدفوعة من صفحة الخدمة نفسها. العامل المدمج يعمل على المدفوعة أيضًا، ويمكنك إيقاف المراقب الخارجي.

### 5.ب الخطة المدفوعة: Blueprint بخدمتين

**جهّز قبل أن تبدأ** سبع قيم في مدير كلمات المرور:
- `DATABASE_URL`: رابط Session pooler (3.1).
- `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` (3.1).
- `SESSION_SECRET` و`DATA_HASH_KEY` و`SECRETS_ENCRYPTION_KEY`: قيم جديدة من `gen_secrets.py --print` (3.2)، لا قيم جهازك.
- `APP_BASE_URL`: اكتب `https://sales-agent-web.onrender.com`، وتصحح لاحقًا إن أعطتك Render رابطًا مختلفًا (الخطوة 4).

1. **المستودع:** الكود على GitHub. يفضَّل أن يكون خاصًا (GitHub ← Settings ← Change visibility).
2. **Render:** من [dashboard.render.com](https://dashboard.render.com) اختر **New ← Blueprint**، واربط حساب GitHub، واختر المستودع وفرع `main`. سيقرأ `render.yaml` ويعرض:
   - `sales-agent-web`: الواجهة.
   - `sales-agent-worker`: العامل. كل البحث والإرسال والمزامنة والجدولة تعمل فيه.
   - مجموعة المتغيرات `sales-agent-shared`: البيئة والمنطقة الزمنية فقط.
3. **ستطلب منك اللوحة القيم السبع مرة واحدة** لخدمة الويب. العامل ينسخها منها تلقائيًا. الصق كل قيمة في خانتها ثم **Apply**. يبدأ النشر الأول وتُنشأ الجداول في Supabase تلقائيًا (`alembic upgrade head` قبل الإقلاع).
   إن نقص متغير أو كان خاطئًا، يرفض التطبيق الإقلاع ويكتب السبب بالعربية في سجل الخدمة (Logs).
4. **صحّح الرابط إن لزم:** افتح `sales-agent-web` وانظر رابطها أعلى الصفحة. إن اختلف عما كتبته، عدّل `APP_BASE_URL` من **Environment** في خدمة الويب، ثم **Manual Deploy** للخدمتين.
5. **تحقق:** يجب أن يعيد `https://<رابطك>/health/ready` الحالة 200، وأن يظهر في سجل العامل `worker … started`.
6. **اربط حسابك بمساحة العمل** من جهازك، موجهًا إلى قاعدة الإنتاج. في PowerShell:
   ```powershell
   $env:DATABASE_URL="<رابط Session pooler>"; $env:APP_ENV="development"; uv run python scripts/add_member.py --workspace-name "اسم شركتك" --auth-user-id <UID من Supabase> --email you@yourdomain.com --name "اسمك" --role owner --phone-region SA
   ```
   كرر لكل مؤسس (`--role reviewer` لمن يراجع فقط). أغلق نافذة PowerShell بعدها حتى لا يبقى الرابط في الجلسة.
7. **ادخل** من `https://<رابطك>/login` ببريدك وكلمة مرورك في Supabase، وأكمل المرحلة ج (صفحة الإعدادات).
8. **ويب هوك Hostinger** (3.5 ب): الصق السر في الإعدادات ← البريد ← «سر ويب هوك Hostinger». لا حاجة لإعادة النشر. تيليجرام يعمل بوضع polling دون إعداد إضافي.

**متغيرات تضيفها لاحقًا بيدك** (Environment Groups ← `sales-agent-shared` ← Add):
- `OUTBOUND_ALLOWLIST` و`OUTBOUND_ENABLED`: في المرحلة هـ فقط.
- كل تعديل في المجموعة يحتاج **Manual Deploy** للخدمتين. Render يحفظ ما تضيفه من اللوحة ولا يمسحه عند مزامنة الـBlueprint.

**الأسعار:** الخدمتان على خطة `0.5c-512mb` (Starter سابقًا)؛ راجع [render.com/pricing](https://render.com/pricing) و[supabase.com/pricing](https://supabase.com/pricing). لا تستخدم الخطة المجانية لخدمة الويب: تنام بعد فترة خمول، فتتأخر أو تضيع ويب هوكات Hostinger وتيليجرام. تكلفة النماذج لا تتجاوز الميزانية التي تحددها، والبحث والخرائط غالبًا داخل الحصص المجانية.

## 6) المرحلة هـ: فتح الإرسال تدريجيًا (بقرارك أنت)

1. **تجربة مغلقة على بريدك:** في Render أضف إلى مجموعة `sales-agent-shared`: `OUTBOUND_ALLOWLIST=you@yourdomain.com` (يقبل أيضًا نطاقًا كاملًا مثل `@yourdomain.com`) و`OUTBOUND_ENABLED=true`، ثم **Manual Deploy** للخدمتين.
   - أضف في المنصة شركة اختبار (الاستيراد ← إدخال يدوي) جهة اتصالها بريدك الثاني، ووثّق سندها «اختبار داخلي».
   - ثم الفرصة ← «معالجة الآن» ← اعتمد من تيليجرام أو اللوحة.
   - تحقق من ثلاثة أمور: الرسالة وصلت إلى صندوقك، وظهرت في مجلد «المرسل» في Hostinger، وأن الرد عليها ظهر في «المحادثات» خلال دقائق.
2. **الإرسال للعملاء:** احذف `OUTBOUND_ALLOWLIST` من المجموعة وأعد نشر الخدمتين. من هذه اللحظة، كل رسالة تعتمدها تُرسل فعلًا.
3. **التشغيل المجدول:** الإعدادات ← التشغيل ← وضع التشغيل «فعلي». يُرفض التحويل إن نقص شرط؛ اللوحة تسرد النواقص.
4. **الطوارئ:** صفحة «اليوم» ← التحكم ← «إيقاف الإرسال» أو «إيقاف كل المعالجة» يعمل فورًا. وللإغلاق التام: `OUTBOUND_ENABLED=false` في المجموعة وإعادة نشر الخدمتين.

## 7) مثال متكامل: «منظم المواعيد» لعيادات الرياض

**الفئة** (الفئات ← جديدة):
- الاسم: العيادات ومحلات الخدمات بالمواعيد.
- قواعد الملاءمة: تعتمد على المواعيد.
- الاستبعاد:
  - لا تُجمع بيانات مرضى.
  - غياب حجز ظاهر ليس إثباتًا لغياب نظام داخلي.

**المنتج** (المنتجات ← جديد):

| الحقل | القيمة |
|---|---|
| الاسم | منظم المواعيد |
| الوصف المختصر | صفحة حجز عامة وتذكير آلي بالمواعيد للمنشآت الصغيرة |
| المشكلة | حجوزات تضيع لأن الحجز بالهاتف فقط وخارج الدوام لا يرد أحد |
| الخصائص المتاحة (سطر لكل خاصية) | صفحة حجز عامة · تذكير بالموعد عبر البريد · تقويم للموظفين |
| غير متاح | تكامل السجلات الطبية · الدفع الإلكتروني |
| مؤشرات الملاءمة | الحجز عبر الهاتف فقط · لا يوجد رابط حجز في الموقع |
| الاستبعاد | منشأة لديها نظام حجز ظاهر ومفعل |
| حالة السعر | يحتاج مراجعة (فلن يذكر أي سعر) |
| الأولوية | 4 |
| الفئات والمناطق | الفئة أعلاه، والرياض |

احفظ، ثم «اختبر فهم النموذج للمنتج»، ثم فعّل المنتج.

**المصادر** (المصادر ← جديد)، كلاهما مرتبط بالفئة:
- «خرائط Google (Places API)»: يبحث بعبارات مثل «عيادة أسنان الرياض».
- «بحث ويب»: يلتقط المنشآت التي تذكر مشكلتها في صفحاتها.
- لكل منهما: فحص عينة ← راجع النتائج ← أكّد البنود ← فعّل. الدورة اليومية تختار أحد المصادر النشطة بالتناوب الموزون.

**الإعدادات:**
- النماذج:
  - الاستخراج: Anthropic، `claude-haiku-4-5`.
  - التأهيل والصياغة: Anthropic، `claude-sonnet-5`.
  - اختر الأسماء الدقيقة من «جلب النماذج المتاحة»؛ الأسعار تُعبأ، راجعها.
  - علّم مربع اعتماد المعالجة.
- التشغيل: ميزانية يومية 2 وشهرية 40 (USD)، و3 فرص يوميًا، والمواعيد الافتراضية.
- البريد:
  - Hostinger، و`sales@yourdomain.com`، والتوقيع «فريق … – 05xxxxxxxx».
  - سطر الإيقاف: «إن لم يكن هذا مناسبًا لكم، يكفي الرد بكلمة «إيقاف» ولن نراسلكم مجددًا.»
  - حد 20 رسالة يوميًا.
- البحث: Tavily بالسعر 0، و`SA`، و`ar`، و3 استعلامات، و20 مرشحًا. خرائط Google بالسعر 0.

**ما سيحدث:**
1. **09:00:** يختار «منظم المواعيد × العيادات × الرياض» ويبحث بعبارات مثل «عيادة أسنان الرياض الحجز عبر الهاتف». يسجل نحو 20 جهة، مع دليل لكل منها (الرابط ومقتطف منه).
2. **10:00:**
   - يأخذ أعلى مرشح ويقرأ حتى 3 صفحات من موقعه، ويجد بريد التواصل المنشور.
   - يقيّم من الأدلة فقط. مثال: دليل الحاجة 30/35، الملاءمة 25/30، وضوح التواصل 15/20، التوقيت 8/15. المجموع **78**، فيتأهل.
   - يكتب مسودة ويفحصها: لا سعر، ولا خاصية غير متاحة، ولا رابط غير معتمد.
3. **بعد ثوانٍ:**
   - تصلك بطاقة تيليجرام: «مجمع عيادات … · منظم المواعيد · 78/100» مع النص وأزرار «✅ اعتماد / ✖️ رفض / ⏸ تأجيل».
   - إن كانت أهلية المستلم «غير معروفة»، يرفض الاعتماد ويطلب توثيق السند من اللوحة. مثال سند: «بريد الاستقبال منشور في صفحة تواصل الموقع للاستفسارات».
4. **تعتمد:**
   - يُرسل البريد من `sales@` وتُحفظ نسخة في «المرسل».
   - تصبح الفرصة «تم التواصل»، ولن تُراسَل الجهة بأي منتج آخر قبل 14 يومًا.
5. **يرد العميل «هل يمكن اتصال الأحد؟»:**
   - ويب هوك Hostinger يوقظ المزامنة، فيُربط الرد بالمحادثة ويُصنَّف «طلب موعد»، وتصبح الفرصة «اقتراح موعد».
   - يُقترح رد يحتاج اعتمادك.
6. **لو ردّ «إيقاف»:**
   - يُسجَّل منع تواصل للبريد والجهة فورًا، وتُلغى كل المسودات والأوامر المعلقة لها.
   - لن تظهر هذه الجهة في أي دورة لاحقة.
7. **18:00:** ملخص: كم اكتُشف، وكم تأهل، وما اعتُمد وما أُرسل، والردود، والتكلفة.

## 7.أ) مساعد تيليجرام: اسأل الوكيل عن بياناتك

بعد ربط حسابك (`/link الرمز`)، يرد البوت على أسئلتك:
- **في المحادثة الخاصة مع البوت:** اكتب السؤال مباشرة.
- **في مجموعة الفريق:** `/ask سؤالك`، أو الرد على رسالة من البوت.

| الأمر | ماذا يفعل | يستهلك النموذج؟ |
|---|---|---|
| `/today` | ملخص اليوم: الموافقات، الحصة، الإنفاق، آخر دورة، التنبيهات | لا |
| `/pending` | المسودات بانتظار اعتمادك | لا |
| `/help` | قائمة الأوامر | لا |
| سؤال حر | مثل «ما حالة مجمع عيادات الواحة؟» أو «لماذا رُفضت آخر فرصة؟» | نعم، ضمن الميزانية (فئة assistant) |

- **قراءة فقط:** المساعد لا يعتمد ولا يرسل شيئًا. الاعتماد يبقى لأزرار البطاقات واللوحة.
- **لا يصل للنموذج:** بريد أو هاتف أي جهة اتصال.
- **الإعدادات:** من الإعدادات ← تيليجرام تفعّل الأسئلة الحرة أو تعطلها، وتضبط حدها اليومي لكل عضو (30 افتراضيًا).

## 7.ب) تحميل منتجاتك دفعة واحدة

بدل إدخال كل منتج في النموذج يدويًا، ضع المنتجات والفئات في ملف JSON داخل مجلد `private/` (مستثنى من GitHub)، ثم:

```bash
uv run python scripts/load_catalog.py private/catalog.json
```

الأمر أعلاه **معاينة فقط**: يطبع ما سيُضاف ولا يكتب شيئًا. للكتابة الفعلية أضف `--yes`:

```bash
uv run python scripts/load_catalog.py private/catalog.json --yes
```

- **قاعدة البيانات الهدف:** `DATABASE_URL` في `.env`. السكربت يطبع اسم الخادم أولًا.
- **المنتجات تدخل مسودات:** راجع كل منتج، ثم «اختبر فهم النموذج للمنتج»، ثم فعّله.
- **إعادة التشغيل آمنة:** الموجود بالاسم نفسه لا يُكرر ولا يُعدَّل.

## 8) الروتين اليومي (5–10 دقائق)

- **اليوم:** بانتظار اعتمادك، والحصة، والإنفاق، والتنبيهات.
- **الموافقات:** راجع النص والأدلة خلف كل ادعاء. اعتمد أو عدّل (التعديل ينشئ إصدارًا جديدًا ويُبطل أي اعتماد سابق) أو ارفض.
- **«تسليم غير معروف»:** يعني أن الاتصال انقطع أثناء الإرسال. افتح مجلد المرسل في Hostinger ثم اختر «أُرسلت» أو «لم تُرسل». النظام لا يعيد الإرسال من تلقاء نفسه أبدًا.
- **المحادثات ← تحتاج ربطًا:** رد لم يُعرف بثقة لأي فرصة يعود. اختر الفرصة الصحيحة.
- **واتساب:** إن كانت القناة هاتفًا، يظهر بعد الاعتماد زر «فتح واتساب» بالنص جاهزًا. بعد الإرسال بيدك اضغط «تم التواصل يدويًا».

## 9) النسخ الاحتياطي والاستعادة

```bash
uv run python scripts/backup.py dump
uv run python scripts/backup.py verify backups/<الملف>.dump
```

- `dump` ينسخ مخططي `sales` و`sales_graph` إلى مجلد `backups/` المستثنى من git.
- `verify` يسترجع النسخة في قاعدة مؤقتة، ويعد الصفوف، ثم يحذفها.
- لقاعدة Supabase ثبّت أدوات عميل PostgreSQL بإصدار لا يقل عن إصدار القاعدة؛ السكربت يرفض إن كانت أقدم. خطط Supabase المدفوعة فيها نسخ يومية تلقائية أيضًا.
- التفاصيل في [backup-restore.md](backup-restore.md).

## 10) حل المشكلات الشائعة

| العَرَض | السبب الأرجح | الحل |
|---|---|---|
| التطبيق لا يقلع على Render | متغير ناقص أو https مفقود | اقرأ سطر «إعداد غير صالح» في السجل؛ يسمي المتغير |
| «Internal Server Error» عند الدخول، و`/health/ready` يعيد 503 | الجداول غير منشأة في Supabase | تأكد أن `MIGRATE_ON_START=true` في **Environment** بالخدمة، ثم **Manual Deploy ← Deploy latest commit**. السجل يجب أن يبدأ بـ«تطبيق الترحيلات قبل الإقلاع…» |
| المفاتيح في `.env` ولا يراها Render | `.env` لا يُرفع إلى GitHub عمدًا (حماية الأسرار) | أدخل المتغيرات في صفحة **Environment** بالخدمة على Render (زر **Add from .env** يقبل لصقها دفعة واحدة) |
| لا يظهر `worker … started` في سجل Render | `RUN_WORKER_IN_WEB` غير مضبوط أو النشر من نسخة قديمة | أضف `RUN_WORKER_IN_WEB=true` ثم Deploy latest commit |
| «تعذر جلب مفاتيح التحقق من Supabase» عند الدخول | المشروع على HS256 القديم | 3.1 الخطوة 4 |
| «حسابك غير مرتبط بعضوية» | لم يُشغَّل `add_member.py` | المرحلة د الخطوة 6 |
| اختبار البريد يفشل في SMTP | كلمة مرور خاطئة أو المنفذ 465 محجوب | جرّب 587 مع STARTTLS من «الإعدادات المتقدمة» |
| الردود تتأخر | الويب هوك غير مضبوط | المزامنة الدورية تلتقطها خلال دقائق؛ اضبط الويب هوك (3.5 ب) |
| ويب هوك Hostinger يعيد 401 | السر لا يطابق | انسخ السر الجديد إلى `HOSTINGER_WEBHOOK_SECRET` أو خانته في الإعدادات |
| الاكتشاف يعيد جهات «[اصطناعي]» | البحث ما زال على «اصطناعي» | الإعدادات ← البحث ← Tavily أو Brave، أو خرائط Google |
| خرائط Google تعيد 403 | Places API (New) غير مفعلة، أو الفوترة غير مربوطة، أو المفتاح مقيد على واجهة أخرى | القسم 3.4 ج |
| خرائط Google: «0 بموقع قُرئ» | المنشآت بلا مواقع، أو `SOURCE_FETCH_ENABLED` معطل | راجع سجل التشغيل؛ جرّب نشاطًا أو مدينة أخرى |
